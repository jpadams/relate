# expand-workload

An agent skill that grows a dataset's query workload the way an application
accumulates requirements: the seed queries are round 0, then one capability
per round — filtering and paging, aggregation, subqueries, paths, writes,
Cypher 25 constructs — each round extending queries already proven, all of it
living on the dataset's own model, validated by execution, with the report
diffing round-over-round for regressions.

- `skill/SKILL.md` — the round loop (base → pick capability → grow → validate → diff)
- `skill/references/` — the dependency-ordered capability backlog, growth
  recipes, the validation protocol, sources
- `skill/scripts/` — `run_workload.py` (JSONL or executable adoc; write
  isolation; expectation-aware classification: ok / engine-error /
  expected-error / wrong-error / unexpected-ok / timeout / slow / skipped;
  per-round grouping and regression diffing against `--prev`),
  `workload_to_adoc.py` (validated workload → feature-history AsciiDoc),
  `mine_tck.py` and `mutate_queries.py` (shape inspiration only — nothing
  foreign enters the workload), `build_so_store.py` (fresh SO store)
- `examples/stackoverflow-workload.adoc` — 42 entries grown over 7 rounds on
  the 417-node Stack Overflow store (39 ok, 3 engine-gap probes matched),
  runnable: `run_workload.py examples/...adoc --engine relate --store
  <path>`; the graph-examples nightly runs it. Machine-generated by
  `workload_to_adoc.py` from the validated report — regenerate it, never
  hand-edit; it is consumed whole by `load_workload`, so it stays one file.

Not a crate; no CI wiring — the scripts run on demand. Validated against
the openCypher TCK corpus (1614 patterns mined; the corpus now lives in
the spec-harness checkout's `features/tck/`), against a `relate`
in-memory store (classification incl. a caught write leak as a
protocol violation, perf report), and end-to-end on a 417-node Stack
Overflow store: 3 seed queries from the graph-examples guide, mutated
to 18 more, all 21 validated clean.
